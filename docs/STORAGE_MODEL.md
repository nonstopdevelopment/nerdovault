# Storage Model

Nerdovault uses two local storage layers:

1. macOS Keychain stores one Nerdovault master key.
2. SQLite stores projects, aliases, audit metadata, and encrypted secret values.

## Keychain Item

The Keychain item is:

- service: `dev.nonstop.nerdovault`
- account: `master-key`
- value: random 32-byte vault master key

The master key is generated by Nerdovault. It is not derived from a password and
it is not one of the user's existing macOS passwords.

The Keychain item is a regular generic password item so the CLI can be installed
through Homebrew or `cargo install` without app-bundle keychain entitlements.
Before Nerdovault reads or creates this item, it requires macOS
LocalAuthentication.

By default, Nerdovault uses the `deviceOwnerAuthentication` policy. On Macs
with Touch ID, macOS can satisfy this with Touch ID and can fall back to the
account password path. `nerdovault init --biometry-current-set` uses the
stricter biometric-only LocalAuthentication policy and records the evaluated
biometric domain state so Nerdovault can refuse unlocks after enrolled
biometrics change.

## Vault Database

The database lives under `~/.nerdovault`, unless `NERDOVAULT_HOME` is set:

```text
~/.nerdovault/vault.sqlite3
```

On Unix/macOS, Nerdovault enforces `0700` permissions on the vault directory and
`0600` permissions on `vault.sqlite3` whenever the vault opens. This keeps the
local database out of casual same-machine reads while still allowing the current
user to operate normally.

The database contains:

- project names
- env var names
- alias names
- encrypted secret nonces and ciphertexts
- local audit events
- non-secret settings

The database does not contain plaintext secret values.

## Encryption

Secret values are encrypted with XChaCha20-Poly1305.

Each encrypted value gets a fresh random nonce. Associated data binds ciphertext
to its intended project/key or alias name so ciphertext moved between records
does not decrypt successfully under the wrong identity.

## Manifest

`.nerdovault.toml` is intentionally safe to commit. It may contain:

- project name
- required env var names
- links from project env names to shared aliases

It must never contain secret values.

## Recovery

If the Nerdovault Keychain master key is deleted, the encrypted vault database
cannot be decrypted. v1 does not include backup, escrow, sync, or recovery.
